# Decisions, 2026-11-15

The owner's answers when the team's way of working was set up for WireBuddy, and the earlier standing rules that
stay. Quotes are the owner's own words.

1. **Targets.** Owner: "Linux, Wireshark 4.6 + new: Windows (I can set up a local session on  a windows machine!)".
   Linux with Wireshark 4.6 and Node 22 is the target the budgets and checks are set for. Windows is new and is
   brought up through a session on the owner's Windows machine, with tasks from a queue file. macOS stays
   verified in CI only.

2. **Merging.** Owner chose "Keep: my word each time". The orchestrator opens the pull request and merges to main
   only on the owner's word. The owner tags and releases.

3. **Branches and what is public.** The owner allowed the branches `status`, `evidence/*` and `int/next-batch-*`.
   The repository is open source: the status files (backlog, requirements, status, decisions) are public as plain
   text on the `status` branch; process documents and their tools stay out of the public repository for now.

4. **Commit texts.** No trailers and no tool footers in commit and pull request texts from now on. Existing
   history stays.

5. **Earlier standing rules of the owner, which stay.**
   - Mid-tier models implement, the cheapest tier runs tests, the strongest tier is used only for complicated
     tasks; the orchestrator reviews what they do. (The owner's sentence names the models; it is not quoted here.)
   - "I get ci fail emails all the time - why?" Therefore: no CI run while another runs on the same branch, no
     speculative runs, one macOS probe per change.
   - "If you find bugs of course we need to fix them", "but better put them on a pushed list". Open work is kept
     as a file (the backlog), not as GitHub issues.
